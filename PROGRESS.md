## Phase 1 — Design System ✅ COMPLETE

### Token System ✅
- oklch-based color scale generator (`burq/theme/color.py`)
- Full token compiler (`burq/theme/compiler.py`)
- Theme class with ALL scales derived from user config:
  - `primary` hex → brand-100 to brand-700 via oklch
  - `gray` hex → gray-100 to gray-900 via oklch
  - `color_success/warning/error` → full scales via oklch
  - `spacing_unit` → space-1 through space-12
  - `font_size_base` → text-xs through text-2xl
  - `radius` → fixed scale (0/4/6/8/12/16px)
  - `border_width` → border-width/2/3
  - `shadow_strength` → shadow-sm/md/lg
- Semantic tokens: background, foreground, surface, surface-raised,
  muted, muted-foreground, accent, accent-foreground, border,
  chrome, chrome-foreground, chrome-border
- Status color tokens: color-success/warning/error + dark variants
- Z-index tokens: dropdown(150), sticky(10), sidebar(20), modal(200), toast(300)
- Component tokens: toast, modal, tabs, skeleton, progress

### Layout Components ✅
- `layout` — grid shell with 4 modes
- `topbar` — sticky, left/right slots, theme toggle
- `sidebar` — sticky, logo, nav, footer slots
- `nav-item` — icon + label, active state, collapsed state
- `container`, `row`, `col`, `grid`, `divider`

### UI Components ✅
- `card`, `badge`, `button`, `metric-card`, `table`
- `input`, `textarea`, `select`, `custom-select`, `toggle`, `checkbox`, `radio`
- `toast`, `modal`, `tabs`, `avatar`, `avatar-group`
- `skeleton`, `progress`, `dropdown`, `breadcrumb`, `spinner`, `alert`

### JavaScript Runtime ✅
- `ToastManager`, `ModalManager`, `initTabs()`, `initDropdowns()`
- `initCustomSelects()`, `initTables()`, `initSidebar()`, `initThemeToggle()`
- Table hydration with `column_config` support
- Theme toggle with localStorage persistence

### Backend (CRM Demo) ✅
- FastAPI + SQLite + SQLAlchemy
- Models: Contact, Deal, Activity, DealStatus
- Endpoints: contacts, deals, activities, summary
- Now also serves static dist/ files

```python

    data=bq.fetch("GET", "/contacts/"),
    columns=["name", "company", "status", "value", "created_at", "active"],
    column_config={
        "name":       bq.AvatarColumn(sub_key="email"),
        "status":     bq.BadgeColumn(variant_map={
                          "lead": "default", "qualified": "info",
                          "won": "success",  "lost": "danger",
```

### Known Issue 🔧 NEEDS FIX
- **Routing** — nav links don't work correctly when served via FastAPI
- Current state: each page compiles to separate `.html` file
  (`index.html`, `contacts.html` etc.)
- FastAPI serves `index.html` for all routes via catch-all
- But nav links still point to `/contacts` not `/contacts.html`
- **Solution needed**: client-side routing in `burq.js` using
  `history.pushState` + FastAPI catch-all serving `index.html`
  OR compile all pages into one `index.html` with hidden divs

### Routing Plan (to implement next session)
Two options confirmed:
1. **Multi-page** — keep separate HTML files, FastAPI serves correct
   file per route. Nav links → `/contacts.html`, FastAPI maps
   `/contacts` → `contacts.html`
2. **SPA** — all pages in one `index.html` as hidden divs,
   `burq.js` router shows/hides based on URL,
   FastAPI catch-all always serves `index.html`

**Decision needed at start of next session.**

## Key Design Decisions
1. **Token first** — never hardcode values in components
2. **Context managers** for layout nesting (Streamlit-inspired)
3. **Imperative calls** for leaf components
4. **oklch color scale** — perceptually uniform, one hex → full scale
5. **Lucide icons** — always, no alternatives
6. **Light + dark** — both themes, toggle optional
7. **Static output** — pure HTML/CSS/JS, no server at runtime
8. **column_config** — declarative column rendering, never hardcoded
