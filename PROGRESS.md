## Phase 1 — Design System ✅ COMPLETE

### Token System ✅
- **Filament theme** — `#F08C1A` accent for both light and dark modes
- Light: `#fef9ed` background, `#1a140a` foreground, `#F08C1A` accent
- Dark: `#0a0a0b` background, `#ededee` foreground, `#F08C1A` accent
- Full override params via Theme() — every semantic token overridable
- Spacing, typography, radius, shadow, z-index, component tokens intact

### Layout Components ✅
- `layout`, `topbar`, `sidebar`, `nav-item`, `container`, `row`, `col`, `grid`, `divider`, `spacer`
- **Topbar spans full width** — logo + toggle live in topbar, sidebar starts below
- **Sidebar** `top: 52px`, `height: calc(100vh - 52px)` — always below topbar
- **Toggle before logo** in topbar (hamburger → logo → app title)
- `bordered=False` default — clean borderless chrome, opt-in via `Layout(bordered=True)`
- `show_title=False` default — app title hidden by default, logo wordmark sufficient
- Logo system: `"default"` = burq logo (SVG with wordmark), `None` = no logo, SVG string, or file path
- Logo SVG uses exact paths from palette file — `viewBox="0 0 130 36"`, `scale(0.3)` transform
- Collapse support via `layout--collapsed`
- `box` — styled container with explicit background, border, radius, padding, foreground

### UI Components ✅
- `card`, `badge`, `button`, `metric-card`, `table`
- `input`, `textarea`, `select`, `custom-select`, `toggle`, `checkbox`, `radio`
- `toast`, `modal`, `tabs`, `avatar`, `avatar-group`
- `skeleton`, `progress`, `dropdown`, `breadcrumb`, `spinner`, `alert`
- `accordion`, `empty_state`, `pagination`
- `markdown` — renders markdown via marked.js CDN
- `contact_profile` — self-hydrating profile header for detail pages
- `file_upload` — drag and drop zone with preview, accept filter, helper text

### JavaScript Runtime ✅
- `ToastManager`, `ModalManager`, `initTabs()`, `initDropdowns()`
- `initCustomSelects()`, `initTables()`, `initSidebar()`, `initThemeToggle()`
- `initActiveNav()` — active nav via data-href + URL match
- `initUrlParams()` — extracts URL params into window.__burqParams
- `initTableExport()` — client-side CSV export
- `initAccordions()` — toggle panels, supports multiple=True
- `initFileUploads()` — drag/drop, click-to-browse, preview, clear
- `initCharts()` — Chart.js hydration for line, bar, area, donut
- `initNavGroups()` — collapsible sidebar groups, auto-open on URL match
- `burqClearFile(uid)` — global helper to reset file upload
- Table search + pagination (client-side, PAGE_SIZE=10)
- Table row click — `row_href` param navigates to detail page
- Empty state — shown when table data is empty or search returns no results
- Theme toggle with localStorage persistence
- Arrow function fix — proper closure scope for multiple tables per page

### Backend (CRM Demo) ✅

```python
bq.bar_chart(data=df, x="month", y="revenue", title="Revenue", height=300)
```

## Phase 3 — Compiler ✅ COMPLETE

### Routing ✅
- **Burq never generates route files** — FastAPI owns all routing
- Each `@app.page("/route")` → Jinja2 template only
- Dynamic routes → inline param extraction script + `window.__burqParams`
- `Burq.fetch()` interpolates `{param}` from `__burqParams`

### CSS Generation ✅
- `css_gen.py` generates all three CSS files internally
- No file copying, no dev folder dependency
- `generate_css(theme)` → `tokens.css`
- `generate_layout_css()` → `layout.css`
- `generate_components_css()` → `components.css`

### Architecture ✅
```
FastAPI  → routing, auth, data APIs, serving templates
Burq     → compile .py → .html templates + JS + CSS
Browser  → JS reads URL params, fetches data from FastAPI APIs
```

## Phase 6 — CLI ✅ COMPLETE

### Commands ✅
```bash
burq new my-app    # scaffold project → app.py + pages/ + components/ + .gitignore
burq build         # compile app.py → dist/ with build timer
burq dev           # watch app.py + pages/ + components/ → recompile on change
```

### Key behaviors ✅
- `burq dev` watches for `.py` changes, debounces 300ms, skips `dist/` and `__pycache__`
- `burq build` shows per-file output + total build time in ms
- Auto-detects `bq.App` instance in `app.py` — no config file needed
- Pages defined anywhere (inline or imported) are auto-compiled as long as `@app.page` runs before `compile_app()`
- UTF-8 encoding on all scaffold file writes (Windows compatible)
- Installed via `pip install -e .` → `burq` command available globally in venv

## Key Design Decisions
1. **Token first** — never hardcode values in components
2. **Context managers** for layout nesting (Streamlit-inspired)
3. **Imperative calls** for leaf components
4. **Filament theme defaults** — `#F08C1A` accent, both light + dark
5. **Lucide icons** — always, no alternatives
6. **Light + dark** — both themes, toggle optional
7. **FastAPI owns routing** — Burq compiles templates only, no route generation
8. **column_config** — declarative column rendering
9. **Logo system** — default SVG with wordmark, None, SVG string, or file path
10. **Dynamic routes** — `{param}` in page path → JS extracts from URL
11. **bordered=False default** — clean borderless chrome, opt-in
12. **Topbar owns logo** — sidebar is nav-only, logo always visible
13. **CSS fully generated** — no file copying, css_gen.py owns all output
14. **show_title=False default** — wordmark in logo SVG is sufficient
15. **Burq is a compiler** — user brings their own backend/server
16. **Charts use Chart.js** — CDN injected at compile time, colors from theme tokens
17. **Error messages point to user code** — burq internals skipped in traceback
